## 指示文（GitHub Copilot Chatへ投入）

このプロジェクトでは、設計と最終決定は私が行います。
あなたは「実装者」として以下の設計に従ってコードを作成してください。

【制約】
- 設計（型定義や関数の役割）を勝手に変更しないこと
- 新しい外部ライブラリを追加しないこと（Zodはすでにインストール済み）
- 実装前に不明点や懸念があれば質問すること

【指示内容】
1. Zodスキーマの定義 (`src/types/book.ts` または適切なバリデーションファイル):
   - SupabaseのDB行データを表す `BookRow` に対応するZodスキーマ（例: `bookRowSchema`）を定義してください。
   - 新規作成・更新時の入力値（`CreateBookInput` など）に対応するZodスキーマ（例: `createBookInputSchema`）を定義してください。
   - 既存のTypeScript型（`Book`, `BookRow`, `CreateBookInput` 等）とZodスキーマの間で、`z.infer` を活用して型定義の二重管理を防ぐか、整合性を維持してください。

2. APIレスポンスのパースと検証:
   - `src/hooks/useBooks.ts` またはマッパー関数内において、Supabaseから取得した生データ（`BookRow[]` や単一の `BookRow`）を、定義したZodスキーマで検証・パース（`.parse()` または `.safeParse()`）してからマッパーに渡すように実装を修正してください。
   - スキーマ違反のデータが検出された場合、適切なエラーハンドリング（コンソール出力やエラー通知）を行ってください。

3. 入力値の検証:
   - クライアント側（フォーム送信時やフック内での `addBook` / `updateBook` 実行時）において、入力データがZodスキーマを満たしているかを検証する処理を組み込んでください。

4. エラーハンドリングの統合:
   - Zodのバリデーションエラーが発生した場合のエラーメッセージを分かりやすく処理し、既存の `reportError` などのエラーハンドリング機構と統合してください。
