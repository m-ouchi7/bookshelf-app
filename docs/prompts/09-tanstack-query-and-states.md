# Prompt 09: TanStack Queryの導入とLoading / Error状態の実装

## 実行日
2026-10-17

## 指示文（GitHub Copilot Chatへ投入）

このプロジェクトでは、設計と最終決定は私が行います。
あなたは「実装者」として以下の設計に従ってコードを作成してください。

【制約】
- 設計（型定義や関数の役割）を勝手に変更しないこと
- 新しい外部ライブラリを追加しないこと（TanStack Query、Zodはすでにインストール済み）
- 実装前に不明点や懸念があれば質問すること

【指示内容】
1. TanStack Query (`@tanstack/react-query`) の導入:
   - アプリケーションのエントリーポイントまたは適切なプロバイダー層に `QueryClient` および `QueryClientProvider` を設定してください。
   - 既存の `useBooks` フックをリファクタリングし、サーバーデータの取得・更新（CRUD）に `useQuery` と `useMutation` を使用するように実装を変更してください。
   - 既存のローカル `useState` による `books` の二重管理を廃止し、TanStack Queryのキャッシュを信頼できる情報源（Single Source of Truth）としてください。

2. ローディング・エラー・空状態のハンドリング:
   - `useQuery` から返される `isLoading`（または `isPending`）、`isError`、`error` などの状態をフックの戻り値に含め、画面コンポーネント側で受け取れるようにしてください。
   - ホーム画面（本一覧）において、以下の状態に応じた表示分岐を実装してください：
     - **初回取得中**: ローディング表示（スケルトンまたは読み込み中表示）
     - **取得失敗**: エラーメッセージおよび再試行（retry）導線
     - **データ0件**: 「本が登録されていません」および新規追加への誘導
     - **データあり**: 書籍一覧の表示

3. CRUD操作後のデータ同期と通知:
   - 追加・更新・削除のミューテーション成功時は、`queryClient.invalidateQueries` を使用してキャッシュを無効化し、最新データを再取得してください。
   - 操作の成功時・失敗時には、モーダルではなく簡易的な通知（トースト通知または適切なインラインメッセージ）を用いて結果をユーザーに伝えてください。

4. 画面側のUI・状態分離:
   - 検索ワード（`searchQuery`）やフィルター状態（`filterStatus`）などのUI固有のローカルステートは、サーバーデータとは分離して維持し、Queryから取得したデータに対してフィルタリング処理を行ってください。
